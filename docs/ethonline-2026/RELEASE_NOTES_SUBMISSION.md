### What I submitted

An x402 payment gate that refuses **before a signature exists**, judged on live on-chain evidence rather
than on my word:

- **`payOrRefuse`** in `@vet402/sdk` (`packages/sdk/src/pay-or-refuse.ts`) — reads the seller's settled
  history from vet402's `/decision` and, as a second evidence source, directly from the x402 Base subgraph on
  The Graph (`packages/sdk/src/subgraph-evidence.ts`); pays only when the verdict is ALLOW. BLOCK cannot be
  switched off by the caller; every malformed input (amount, policy, body shape, gateway/origin mismatch)
  stops before signing.
- **`pay_if_trusted`** in `@vet402/mcp-server` (`packages/mcp-server/src/pay-if-trusted.ts`) — the same gate
  as an MCP tool, so an agent reaches the signer only through the verdict.
- **`examples/ethonline-2026-demo`** — `refuse`, `pay` (dry run: fetches the real 402, signs nothing) and
  `judge <url>` (bring your own x402 URL).
- **`examples/ethonline-2026-ab`** — the Bazantic A/B harness (Recipe vs no Recipe), with the raw logs of
  the real runs under `docs/ethonline-2026/ab/`.
- On 2026-09-05 the gate signed and settled a real **$0.01 USDC** payment to The Graph's own x402 endpoint
  on subgraph evidence alone — tx `0xf12093fb…e469ad` on Base (linked from `SKILL.md`).

Numbers that move (test counts, mutation counts, files added/modified in the window) are not repeated here;
they live in `README.md` / `SKILL.md` / `AI_USAGE.md` behind `scripts/refresh-numbers.mjs --check`, which CI
runs on every push. As of this release: `✔ 12 number(s) consistent across 8 doc(s), 46 mark(s) — 7 derived now, 5 against recorded values (2 of them guarded)`.
