## 2. AI が AI へ出した指示 — 要点

### 2.1 提出物の独立監査（sub-agent・read-only）
- **提出物の断定を1つずつ、コマンドで再現できるか**を検査させた。「数字は書き手が出したものを信じない。
  `git log pre-ethonline-2026..main` 等で自分で数え直し、合わない箇所を列挙する」
- 結果: 5 つの数字が再現しなかった（207/679/560/64/108 → 214/684/565/139/160）。全部直した（`f844ae6`）

### 2.2 A/B ハーネスの作り直し（sub-agent・worktree `/tmp/vouch-ab`・ブランチ `ethonline/ab-harness`）
- 条件 B は `SKILL.md` ではなく **bazantic.com で作った Recipe**。MCP を**実際に経路へ入れる**
  （Streamable HTTP の 3 手だけを自前で実装。SDK を足さない）
- 「**状態を固定するテスト**」を禁じた: 「`liveReady` は false であること」のような表明は改善したら赤くなる。
  **規則を両方向で書く**（blockers があるとき false・無いとき true）
- 秘密の検出は 64 桁 hex を一律に弾かない。**公開して良い hex（tx ハッシュ）の許可リスト**を持つ

### 2.3 Bazantic の 402 に対する橋（sub-agent・同 worktree）
執行部の実走で A 0% / B 0%。原因を一次情報で確定したうえで出した指示の中核:
- 「ゲートウェイは $0 でも 402 を返す（Bazantic 既定・設定で外せない）。**MCP の POST に `PAYMENT-SIGNATURE` を載せても無視される**（実署名で実測）。REST なら $0 の x402 が実決済される（tx `0x061702d4…fa932`）」
- 「ツール結果が **$0 の x402 402** だったときだけ、自分で署名して REST へ回す。**`amount !== "0"` なら署名せず fail-loud**。A/B の両条件に同一に効く。署名回数と tx を生ログに残す」
- 「テストはネットワーク不要（`fetchImpl` 差し替え）。状態固定ではなく規則で書く。変異を 3 つ以上足し、全部赤くなることを確認する」
- 「`git add -A` 禁止。`docs/` と `results/` は触らない。push しない」
