## 2. AI が AI へ出した指示 — 実装（原文の要点）

実装は sub-agent へ委任した。プロンプトの中核（全文は git 履歴の本ファイル初版）:

- 作業ツリーは `git worktree`（`/tmp/vouch-ethonline`・ブランチ `ethonline/payorrefuse`）。
  **`~/vouch` 本体は触らない**（`~/vouch` = このリポの保守者ローカルの checkout。他セッションが並行使用）。**push しない**
- **`superpowers:test-driven-development` と `verification-before-completion` を起動してから着手する**
- **仕様はテストファイル**（`packages/sdk/test/pay-or-refuse.test.mjs`）。冒頭の「4層の証明」に従う
- **先に red を書き、赤いことを目で確認してから実装する**
- **偽の緑を作らない。** `assert.rejects` は「未実装だから落ちた」でも通る。
  **理由の中身**（理由コードを正規表現で）と**判定を何回引いたか**を必ず併せて検査する。
  依頼元は 09-04 にこれで偽の緑を2本出している
- **拒否経路で signer に到達できないこと**を、回数ではなく **Proxy のプロパティ参照0**で示す。
  支払い処理は **ALLOW ブランチ内の動的 import**
- **fetch は必ず引数で受け取る**（テストが差し替える）
- 完了条件は `ℹ fail 0` の実出力・`git log`・`git status`・I23 の実在を grep で示すこと
- 報告には**やり残し**と**見つけた仕様/正典の誤り**を必ず含める

### 先に直させた欠陥（依頼元が着手前に発見）

Day 0 に置いたテストは `await import("../src/pay-or-refuse.js")` と書いていた。
このパッケージは `rootDir: src` / `outDir: dist` で、既存テストは全部 `../dist/index.js` から import する。

## 3. AI が AI へ出した指示 — 是正（同日・1回目の報告を受けて）

1回目の実装は緑になったが、**アーキテクチャの誤りが1件あった**。依頼元が本番実装
（`src/lib/observatory/l1-runner.ts` L977-1045）を読んで確認し、2回目の指示を出した:

- **買い手は facilitator を呼ばない。** 署名ヘッダを付けて**売り手へ再送**し、
  決済レシートは**応答ヘッダ**（`PAYMENT-RESPONSE` / `X-PAYMENT-RESPONSE`）から読む。
  実装は架空の `https://x402.org/facilitator` へ settle を投げていた。
  **09-08 の The Graph への実支払いが止まるところだった**（→ WINDOW_PLAN §14）
- **第3層の証明を実装する。** 「支払いは動的 import で、拒否経路では評価されない」と宣言しているのに、
  **static import に戻してもどのテストも赤くならなかった**。主張だけあって検算できない状態だった。
  ソースを検査するテストを足し、**変異（static import に書き換え）で赤くなることを示してから戻す**
- **B5/B6/B7 の偽の緑を塞ぐ**（A1/A2 と同じ穴）
- **F19/F20 の保存先を決定**: 1本のローカル追記専用 JSONL に、行ごと `source` で区別して入れる。
