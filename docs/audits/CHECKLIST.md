# 監査の常設項目

どの監査（セキュリティ・SEO・UX・資金・アクセシビリティ、指示文が何であれ）でも、
**「主張と実測の突合」を必ず 1 次元として見る。** 見るのは 3 つ:
(1) `npm run claims:canary` を走らせ、`failed` が空であること、
(2) `npx tsx --test tests/claims-registry.test.ts` が緑であること（未登録の断定が公開面に入っていない）、
(3) 今回の監査範囲で読んだ公開コピーの断定が `docs/claims.yaml` の `means` と食い違っていないこと。
`check: null` の主張は「確かめられないもの」であって「確かめたもの」ではない — 監査記録にそう書く。

**根拠（この項目が在る理由）**: 2026-08-13 の LP は
「every catalog-listed x402 endpoint, **probed daily**」と書いていた。2026-08-20 に
同じサイトの `/observatory/state` が実測 **18.8%（2,750 / 14,662）** を印字した。
主張と実測が同一サイト内で矛盾したまま **20 日間**公開され、その間に走った
**6 回の監査はどれも気づかなかった** — どの監査の指示文にも「言っていることは本当か」が
入っていなかったからである。外部の観測所 probe402 が 2026-09-01 に読み取り 09-03 に公開し、
我々は 09-02 の自己監査で見つけて直した（僅差）。訂正は `/corrections` に公開済み。
規律ではなく道具にしたのが `docs/claims.yaml`・`tests/claims-registry.test.ts`・
`scripts/claims-canary.ts` の 3 点で、このチェックリストはそれを毎回の監査に接続する。
